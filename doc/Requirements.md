 # 1\. الهدف الأساسي

 التطبيق عبارة عن أداة لإدارة ونقل مجلدات الأفلام والمسلسلات.

 يستطيع المستخدم إضافة عدة مجلدات كمصادر.

 يمكن أن تكون المصادر:

 - مجلدات محلية.
- أقراص داخلية.
- أقراص خارجية.
- مجلدات على شبكة محلية.
- مسارات Windows UNC.

 أمثلة:

```
\\Server\Share
\\Server\Share\Movies
\\Server\Share\TV
\\192.168.1.100\Media
```

 يقوم التطبيق بفحص المجلدات الموجودة داخل المصادر، والتعرف على محتواها، ثم استخدام TMDB API لتحديد نوع المحتوى والتصنيف العمري.

 إذا كان المحتوى يحمل تصنيفاً مستهدفاً للكبار، يتم نقل المجلد بالكامل إلى مجلد وجهة يحدده المستخدم.

---

 # 2\. مبدأ الأمان الأساسي

 البرنامج يجب أن يكون:

 **Fail Closed**

 أي:

 إذا لم يستطع البرنامج التأكد من أن المحتوى مؤهل للنقل، فلا ينقله.

 مثلاً إذا:

 - لم يجد المحتوى في TMDB.
- لم يجد التصنيف.
- فشل الاتصال.
- كانت نتيجة البحث غير موثوقة.
- حدث خطأ في قراءة الملفات.
- حدث خطأ في الوصول إلى الشبكة.

 فالقرار الافتراضي:

 **عدم النقل.**

 سلامة بيانات المستخدم أهم من اكتمال عملية النقل.

---

 # 3\. واجهة المستخدم

 أريد واجهة Desktop احترافية وحديثة وسهلة الاستخدام.

 لغة الواجهة الأساسية:

 **العربية**

 مع إمكانية ظهور بعض المعلومات التقنية بالإنجليزية عند الحاجة.

 يجب أن تدعم الواجهة:

 - Unicode.
- العربية.
- الإنجليزية.
- أسماء الملفات والمجلدات العربية.
- RTL قدر الإمكان حسب قدرات التقنية المختارة.

 يجب ألا تكون الواجهة مجرد نافذة بدائية.

 اجعل التصميم واضحاً ومنظماً.

---

 # 4\. الصفحة الرئيسية

 يجب أن تحتوي الواجهة الرئيسية على الأقسام التالية:

 ## مصادر الفحص

 قائمة تعرض مجلدات المصدر.

 الأزرار:

 - إضافة مجلد.
- حذف المحدد.
- حذف الكل.

 يجب منع إضافة نفس المصدر أكثر من مرة.

---

 ## مجلد الوجهة

 حقل يعرض مسار الوجهة.

 زر:

 **استعراض**

 يتيح للمستخدم اختيار المجلد.

 إذا لم يكن المجلد موجوداً، يمكن إنشاؤه تلقائياً بعد التحقق من صحة المسار.

---

 ## TMDB API Key

 حقل لإدخال مفتاح TMDB.

 يجب إخفاء قيمة المفتاح أثناء الإدخال.

 لا تعرض المفتاح في سجل العمليات.

 لا تحفظه في ملف نصي بدون طلب صريح من المستخدم.

---

 # 5\. أزرار التحكم

 يجب وجود:

 **بدء الفحص والنقل**

 و:

 **إيقاف**

 عند بدء العملية:

 - يتم تعطيل الإعدادات التي لا يجب تغييرها أثناء التشغيل.
- يتم تفعيل زر الإيقاف.

 عند انتهاء العملية:

 - تعاد الواجهة إلى حالتها الطبيعية.
- يتم تحديث الإحصائيات.
- يظهر ملخص نهائي.

---

 # 6\. العمل في الخلفية

 يجب ألا تتجمد واجهة المستخدم أثناء:

 - فحص الملفات.
- فحص المجلدات.
- الاتصال بـ TMDB.
- معالجة النتائج.
- نقل المجلدات.
- التعامل مع الشبكة.

 استخدم آلية مناسبة للمنصة والتقنية التي اخترتها لتنفيذ العمليات الثقيلة في الخلفية.

 يجب أن تبقى الواجهة:

 - قابلة للتحريك.
- قابلة للتحديث.
- قابلة لإظهار Log.
- قادرة على استقبال أمر الإيقاف.

 **لا تجعل العملية الرئيسية الخاصة بالواجهة تنتظر عمليات الشبكة أو النقل.**

---

 # 7\. الإيقاف الآمن

 زر الإيقاف لا يعني قتل العملية بالقوة.

 عند الضغط عليه:

 1. يتم تسجيل طلب الإيقاف.
2. لا يتم قطع عملية نقل جارية.
3. يتم إكمال المجلد الحالي.
4. بعد انتهاء المجلد الحالي، تتوقف معالجة المجلدات الجديدة.
5. يظهر للمستخدم أن الإيقاف تم بأمان.

 لا تستخدم أساليب تؤدي إلى ترك الملفات في حالة غير مكتملة.

---

 # 8\. الفحص الأولي للمجلد

 قبل إرسال اسم المجلد إلى TMDB، يجب التحقق من أنه يحتوي على محتوى فيديو.

 امتدادات الفيديو المستهدفة:

```
mp4
mkv
avi
mov
wmv
flv
webm
```

 يجب أن يكون الفحص غير حساس لحالة الأحرف.

 مثلاً:

```
Movie.MKV
Movie.mkv
Movie.MkV
```

 كلها صالحة.

 يجب عدم اعتبار مجلد لا يحتوي على فيديو محتوى صالحاً للنقل.

---

 # 9\. نطاق الفحص

 المصدر قد يحتوي على:

```
Movies/
    Movie A/
    Movie B/
    Movie C/

TV/
    Series A/
    Series B/
```

 افحص المجلدات الموجودة داخل المصدر.

 إذا كان هناك خيار للفحص المتكرر داخل المجلدات الفرعية، اجعله واضحاً في الإعدادات.

 لكن عند اكتشاف محتوى، يكون النقل على مستوى **المجلد الرئيسي للمحتوى بالكامل**.

---

 # 10\. نقل المجلد

 عند التأكد من أن المحتوى مؤهل:

 يجب نقل المجلد بالكامل.

 مثال:

```
Source:
\\Server\Media\Movies\Movie A

Destination:
D:\Adult Media
```

 النتيجة:

```
D:\Adult Media\Movie A
```

 لا تنقل الملفات واحداً واحداً إذا كان بالإمكان نقل المجلد بالكامل.

 لا تحذف المجلد الأصلي يدوياً.

 لا تستخدم أي عملية حذف كجزء من سير العمل الطبيعي.

---

 # 11\. منع الكتابة فوق البيانات

 إذا كان:

```
Movie A
```

 موجوداً مسبقاً في الوجهة، لا تستبدله.

 أنشئ اسماً فريداً:

```
Movie A_1
Movie A_2
Movie A_3
```

 أو نظام تسمية آمن ومناسب.

 يجب ألا يفقد المستخدم مجلداً موجوداً مسبقاً.

---

 # 12\. استخراج اسم الفيلم أو المسلسل

 يجب أن تكون هناك طبقة مسؤولة عن استخراج الاسم الحقيقي للمحتوى من اسم المجلد.

 أسماء المجلدات قد تكون مثلاً:

```
Breaking.Bad.S05.1080p.WEB-DL
The.Matrix.1999.2160p.BluRay
Game.of.Thrones.Season.01.1080p
Movie.Name.2024.4K.WEB-DL
```

 يجب تحويلها إلى اسم بحث مناسب، مثل:

```
Breaking Bad
The Matrix
Game of Thrones
Movie Name
```

 استخدم مكتبة متخصصة لاستخراج بيانات أسماء الوسائط إذا كانت التقنية المختارة توفر خياراً موثوقاً.

 وإذا لم تنجح، استخدم Parser/Regex احتياطي.

 # 15\. TMDB API

 استخدم TMDB API الرسمي.

 لا تستخدم Web Scraping.

 لا تعتمد على صفحات HTML.

 لا تستخدم مواقع غير رسمية كمصدر للتصنيف.

 يجب أن يكون الاتصال بـ TMDB عبر REST API.

 # 16\. دالة البحث الرئيسية

 أنشئ طبقة أو دالة مركزية مسؤولة عن:

```
get_media_rating(media_name, api_key, year=None)
```

 لا يشترط أن يكون الاسم الداخلي للدالة مطابقاً إذا كانت التقنية المختارة لا تستخدم هذا النمط، لكن يجب أن توجد وظيفة مكافئة لها.

 يجب أن تعيد معلومات واضحة تشمل:

 - التصنيف.
- نوع المحتوى.
- TMDB ID.
- نتيجة البحث.
- حالة البحث.

 الأنواع الأساسية:

```
series
movie
unknown
```

 # 17\. البحث عن المسلسلات

 ابدأ بمحاولة البحث عن المسلسل باستخدام TMDB TV Search.

 استخدم:

```
/search/tv
```

 حاول الاستفادة من السنة عند توفرها.

 لا تعتمد على أول نتيجة دون أي تحقق.

 حاول اختيار النتيجة الأكثر تطابقاً مع الاسم والسنة.

---

 # 18\. تصنيف المسلسلات

 بعد العثور على TV ID، استخدم:

```
/tv/{id}/content_ratings
```

 أعطِ الأولوية للولايات المتحدة:

```
US
```

 واستخرج:

```
rating
```

 إذا لم يوجد تصنيف US، يمكن استخدام تصنيف بديل واضح مع تسجيل ذلك في Log.

---

 # 19\. البحث عن الأفلام

 إذا لم يتم العثور على مسلسل مناسب، ابحث عن الفيلم باستخدام:

```
/search/movie
```

 استخدم السنة عند توفرها.

 يجب تقييم مدى تطابق نتيجة الفيلم مع الاسم قبل اعتمادها.

---

 # 20\. تصنيف الأفلام

 بعد العثور على Movie ID استخدم:

```
/movie/{id}/release_dates
```

 ابحث عن:

```
US
```

 ثم استخرج:

```
certification
```

 من بيانات الإصدار.

 الأولوية لتصنيف الولايات المتحدة.

 قرار النقل يجب أن يعتمد على التصنيف الذي تم الحصول عليه من TMDB.

 # 23\. عدم العثور على المحتوى

 # 24\. دقة البحث

 يجب محاولة منع الحالات التي يبحث فيها البرنامج عن فيلم خاطئ يحمل اسماً مشابهاً.

 رتب النتائج باستخدام عوامل مثل:

 1. تطابق الاسم.
2. السنة.
3. التشابه النصي.
4. ترتيب نتيجة TMDB.

 إذا كانت الثقة منخفضة جداً، لا تنقل.

---

 # 25\. Rate Limiting

 يجب احترام حدود TMDB API.

 لا ترسل آلاف الطلبات بشكل سريع.

 إذا حدث:

```
429 Too Many Requests
```

 استخدم Retry محدوداً مع Backoff.

 مثلاً:

```
1 ثانية
2 ثانية
4 ثوانٍ
```

 ثم توقف عن المحاولة بعد عدد محدود.

 لا تستخدم Loop لا نهائي.

 # 32\. المسارات الشبكية

 يجب اختبار التصميم مع:

```
\\Server\Share
\\NAS\Movies
\\192.168.1.10\Media

 يجب عدم افتراض وجود حرف Drive.

- صلاحيات الوصول.
- المجلد غير المتاح.
- بطء الشبكة.
- الملفات قيد الاستخدام.

 إذا تعذر الوصول إلى مجلد، لا تجعل البرنامج كله ينهار.

أسماء إنجليزية
أسماء مختلطة
```

 ويجب أن تعمل المسارات وأسماء المجلدات التي تحتوي على Unicode.

---

 # 34\. الملفات قيد الاستخدام

 إذا كان المجلد يحتوي على ملفات قيد الاستخدام أو كان النقل غير ممكن:

 - لا تحذف شيئاً.
- سجل الخطأ.
- انتقل للمجلد التالي إذا كان ذلك آمناً.

---

 # 35\. عدم حذف البيانات

 هذا البرنامج:

 **Mover**

 وليس:

 **Deleter**

 لا تضف أي وظيفة تقوم بحذف الملفات تلقائياً.

 لا تستخدم عمليات حذف كجزء من سير العمل.

 إذا فشل النقل، اترك المصدر كما هو.

---

 # 36\. تأكيدات قبل النقل

 قبل النقل يجب التأكد من:

 1. المصدر ما زال موجوداً.
2. المصدر مجلد صالح.
3. الوجهة متاحة.
4. الوجهة ليست داخل المصدر بطريقة خطرة.
5. اسم الوجهة غير مستخدم.
6. المحتوى ما زال موجوداً.
7. القرار ما زال صالحاً.

---

 # 37\. إغلاق البرنامج أثناء التشغيل

 إذا حاول المستخدم إغلاق التطبيق أثناء التشغيل:

 اعرض تحذيراً:

```
هناك عملية فحص ونقل قيد التشغيل.

هل تريد إيقاف العملية بأمان ثم إغلاق البرنامج؟
```

 إذا اختار نعم:

 - اطلب الإيقاف.
- أكمل العملية الحالية.
- انتظر انتهاء Worker بطريقة لا تجمد الواجهة.
- أغلق التطبيق بعد انتهاء العمل.

 إذا اختار لا:

 - أبقِ التطبيق مفتوحاً.

---

 # 38\. حفظ الإعدادات

 لا تحفظ TMDB API Key بشكل دائم إلا إذا كان هناك سبب واضح وتصميم آمن لذلك.

 يمكن حفظ إعدادات غير حساسة مثل:

 - آخر مجلدات المصادر.
- آخر مجلد وجهة.
- تفضيلات الواجهة.

 لكن يجب أن يكون حفظ الإعدادات اختيارياً وآمناً.

---

 # 39\. بنية المشروع

 اختر بنية احترافية مناسبة للتقنية التي ستختارها.

 لا يشترط أن يكون المشروع ملفاً واحداً.

 إذا كانت أفضل ممارسة هي تقسيمه إلى Modules، افعل ذلك.

 مثلاً يمكن أن يحتوي المشروع على طبقات مثل:

```
UI
TMDB Service
Media Parser
File Manager
Configuration
Logging
Tests
```

 لكن لا تستخدم هذه البنية حرفياً إذا كانت التقنية التي اخترتها تتطلب بنية مختلفة.

 **المهم هو التنظيم وقابلية الصيانة.**

---

 # 40\. الاختبارات

 أضف اختبارات تلقائية مناسبة.

 يجب اختبار على الأقل:

 - استخراج اسم الفيلم.
- استخراج السنة.
- تطبيع التصنيف.
- تحديد التصنيف المستهدف.
- اختيار نتيجة TMDB.
- إنشاء اسم وجهة فريد.
- منع نقل مجلد الوجهة إلى نفسه.
- التعامل مع المسارات غير الصالحة.

 اختبارات TMDB يجب أن تستخدم Mock/Stub ولا تعتمد على الإنترنت.

---

 # 41\. الاختبار الحقيقي

 إذا كانت بيئة التطوير تسمح بذلك:

 أنشئ مجلد اختبار يحتوي على:

```
Movie A
Movie B
Series A
Series B
Not Media
```

 ولا تستخدم ملفات حقيقية محمية بحقوق نشر.

 استخدم ملفات فيديو اختبارية فارغة أو ملفات صغيرة مناسبة للاختبار.

 اختبر:

 - المجلد الذي يحتوي على فيديو.
- المجلد الذي لا يحتوي على فيديو.
- مجلد باسم عربي.
- مجلد باسم إنجليزي.
- مجلد موجود مسبقاً في الوجهة.
- فشل النقل.

---

 # 42\. Build للمستخدم النهائي

 اختر أفضل طريقة لإنشاء:

 - EXE
- أو Installer

 بحسب التقنية التي اخترتها.

 لا تجعل المستخدم النهائي مضطراً إلى تثبيت أدوات التطوير.

 - التقنية التي اخترتها.
